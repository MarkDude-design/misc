Native stop-phase semantics
before_call: supervisor saw STOP before launching a worker.
mid_call: worker was already launched. Its own pre-inference STOP check also
reports stage worker_preflight; this does not claim inference had started.
between_calls and unattempted are for Q's batch wrapper to implement.
Older native records without stop_phase must remain unknown unless the wrapper
actually observed enough to classify them. Do not invent stages or metrics.

Corrections to the proposed local run protocol
- Missing middle lock entry: expect ok/error/ok when the first and last models
  are cached and otherwise runnable. The copied lock must actually be the lock
  the isolated test code loads; editing an unused copy proves nothing.
- Uncached GPT-J may fail immediately, so it is not a dependable timeout probe.
  A controlled slow subprocess tests supervisor behavior without weight loading.
- Invalid JSON to the real worker returns JSONDecodeError in a valid JSON error
  record. A deliberate hard exit tests the no-valid-JSON supervisor path.
- Preexisting STOP exits Match Game during its first slot call. To test the
  symbolic-loop bug specifically, STOP must arrive after the last slot result.
- 0.25-second polling is a polling interval, not a hard wall-clock bound.

Q's remaining responsibility
Preserve the complete native record under raw, including diagnostics on success.
Null-fill unavailable fields; catch preflight exceptions at the wrapper boundary.
Preserve requested/framed input, effective timeout, provenance and panel fields.
Keep serial/no-retry behavior, and record remaining calls as unattempted on STOP.
Native CLI tests here do not establish those unimplemented wrapper guarantees.
The API preserves JSON field values, not byte-identical worker stdout. Current
non-streaming generation does not expose partial text on timeout or STOP.
